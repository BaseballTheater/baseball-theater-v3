In words, not drawn:

- Pending Q5: the regular season's page (`phase: "regularSeason"`, or a payload with no `phase`) has no label line, exactly as `standings-*` draw it, with A7 applied.
- The year in the spring label is the payload's `season`. Pending Q4: the day is its `date`, formatted by `formatMonthDay` (`web/src/format/datetime.ts`), which reads it as a calendar day in UTC, so `2027-03-02` reads "Mar 2" in every time zone, never "Mar 1" west of UTC. Pending Q2: the final label's year is its `season`.
- Pending Q3: games back in spring. MLB sends `"-"` as every team's spring `gamesBack` and `divisionGamesBack` (all 30 in the 2026 spring recording), which the standings mapper stores as no value and `DivisionTable` shows as `—`, so the spring frames draw `—` on every row. MLB's spring standings do carry each team's games back within its spring league, Cactus or Grapefruit (`springLeagueGamesBack`, typed in `packages/mlb-api/src/standings.ts`), which Q3 offers as an alternative.
- Ties: spring games can end tied (23 of the 30 teams have at least one in the 2026 spring recording, one of them six). The table shows W and L only, and PCT is MLB's as served. Early in spring a team that hasn't played shows `0`, `0` and MLB's PCT as served. If MLB returns no spring records at all before the first spring game is final, the page shows the final table instead (S128 AC 3).
- Loading, empty and error states are unchanged (`ViewState`) and show no label, since no table is shown.

## Open questions

1. **Q1.** **Is a muted line under the title, "Spring training 2027 · as of Mar 2", the label you want for spring training standings?** That is how it is drawn: the title stays `Standings` and a quieter line under it names the table. Alternatives are a small badge beside the title, or retitling the page "Spring training standings".
2. **Q2.** **Should the off-season final table be labeled too, "2026 regular season · final"?** From the end of the regular season until spring training's first game, Standings shows the last season's final table. If yes, the `standings-final-*` frames stay and FEATURES records your words; if no, those frames and every "Pending Q2" sentence here are dropped, and the final table stays as the ratified frames draw it (with A7), with no label.
3. **Q3.** **In spring, should the GB column show `—` on every row, be hidden, or show each team's games back in its spring league?** MLB gives no division games back for spring training, so as drawn the column is a row of dashes. Hiding it in spring makes the table narrower. The third choice uses a number MLB does send for spring: games back within the team's spring league, Cactus or Grapefruit (`springLeagueGamesBack`). That counts across the whole spring league, not the division the table shows, so the column would need its own heading; it is a change to what the standings mapper passes on, not a new calculation.
4. **Q4.** **Should "as of Mar 2" mean the day asked for, or the last day with finished games?** The label uses the day the page asked for, which is the payload's day: on the morning of Mar 2, before that day's games finish, the records run through Mar 1 but the label says Mar 2. Saying the last finished day instead needs a change to what S128's server sends, so a new story.
5. **Q5.** **Should regular-season standings also show an "as of" line, like "2026 regular season · as of Sep 21"?** Today they show no line under the title. If yes, the regular-season page gets the same muted line and frames are added for it; if no, only spring (and, if Q2 says so, the final table) is labeled.
6. **Q6.** **Should the browser tab and the page's heading for screen readers also say spring training, or only the visible muted line?** As drawn, the heading stays "Standings" and only the line under it changes. If yes, S130 also makes the heading or tab read, for example, "Standings, spring training 2027".
