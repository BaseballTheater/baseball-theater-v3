**Gap:** Baseball Savant's game feed (`https://baseballsavant.mlb.com/gf?game_pk=823823`; owner, 2026-10-30: *"oh, I forgot, there's also this"*) holds every pitch keyed by the live feed's `playId` (340 of 340 on 823823). Most of it repeats MLB's live feed exactly — the trajectory (`x0`…`az`, spin, breaks, extension, plate time), the strike zone, the box score and season lines — but some is in no MLB feed BT reads: per batted ball expected batting average (`xba`), barrel, spray position in feet and how many ballparks a home run leaves (`homeRunBallparks`); bat speed on every swing; sword swings; Savant's in-zone call; times through the order; the exact ABS-challenged pitch; and the location where the pitch crosses the front of the plate. BT keeps only those (owner, 2026-10-30, asked whether to ingest only what BT doesn't already have: *"Yes re: S103"*). Nothing in the feed says when Savant computed them (owner, 2026-10-30: *"Something that needs to be accounted for is the potential difference in arrival time for the baseball savant details. Since the season is over, I can't tell whether there's any time delta in the realtime arrival of these, unless the data itself tells us something useful."*) — it says only that it is built from MLB's game feed and cached (`"source": "gamefeed"`, `cacheKey`).

**Impact:** Before S103, BT knew how a pitch moved but not what Savant makes of it. S103 impact: each pitch carries Savant's extras — how likely a batted ball was to be a hit, the swing's speed, whether a home run would have left other parks — filling in as Savant publishes them, without ever holding up the live game.

4. **Only what MLB's feeds lack.** A mapper projects each pitch, joined by `playId`, into `GameSnapshot.savant` with exactly: `xba`, `isBarrel`, spray `x` / `y` in feet, `homeRunBallparks`, `batSpeed`, `isSword`, `savantInZone`, `timesThroughOrder`, `isAbsChallenge`, and the front-of-plate location (`plateXPoly`, `plateZPoly`); no trajectory, zone, box-score or season field is copied (grep over the mapper), so each value keeps one source (ADR-025). On 823823: 52 batted balls carry `xba`, 150 swings carry `batSpeed`, 2 pitches are swords, and the 5 ABS-challenged pitches are in `atBatIndex` 34, 39, 69, 82, 83 (Savant's `ab_number` is one higher) (tests). Additive to the payload (`pnpm api:breaking` exits 0).
5. **Arrival time is accounted for** (owner, 2026-10-30, quoted in the Gap):
   - Savant is pulled on its own cadence inside S48's ingest object, never in the same call as the live feed, so a slow or failing Savant never delays a pitch (test with a hanging Savant fake);
   - each Savant field is empty until it arrives and is merged into its pitch by `playId` as it does, a newer value replacing an older one only by version (ADR-022), and views read an absent field as "not yet", never as zero (unit tests on the merge);
   - for each pitch BT records when each Savant field first appeared beside the live feed's time for that pitch (`playEndTime`), so the real delay can be read once live games resume (test on a two-poll sequence);
   - polling is bounded: at most every N seconds while the game is in its live window (N in config) and once more after the final for late fields (test).
6. The source is optional: when Savant fails or returns nothing, `savant` is absent and the game is served as before (test).
