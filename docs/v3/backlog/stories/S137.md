**Gap:** Standings shows one day's tables, and both the page and the API already take a day (`/standings?date=<date>`, read by `web/src/pages/StandingsPage.tsx`; `GET /api/v1/standings?date=`), but nothing on the page lets a fan choose it. The owner asked for the scoreboard's date picker there (owner, 2026-11-09: *"can the standings page also have the date picker and show what the standings were at any given date?"*; told the page and the API already take a date, and offered its own stories, a fold into S129's design, or nothing: *"Add as its own stories (Recommended)"*). No ratified frame draws a date control on Standings, so S138 can't build it (rule 18).

**Impact:** Before S137, Standings showed only today's tables unless a fan edited the address by hand. S137 impact: the owner approves how Standings' date picker looks and what the page shows for a past date, before S138 builds it.

**Notes:**

- A ratified file is never edited (CLAUDE.md), so the story writes only an amendment, as the surface's earlier amendments did.
- **What already works.** `StandingsPage` passes `?date=` to `useStandings`, and the answer carries the day its table stands as of (`StandingsSnapshot.date`, `packages/domain/src/types.ts`: for the off-season's final table that is the season's last regular-season day, not the day asked for), its `phase` and its `season` (S128). So AC 3's "what the control reads" is a real choice between the day picked and the day the table is from.
- **Before drawing, check the early seasons.** The mapper groups MLB's records by division (`functions/src/mappers/standings.ts`), and before 1969 the leagues had none. Ask the local API for a date such as 1950-07-04 and look at what it answers; if it isn't one table per league, ask the owner what the page should show rather than drawing a guess.
- **Answers that change the product.** What Standings shows for a season before 1969, or for a day after today, is the owner's call; their words go into FEATURES in the same change (rule 19), which is why FEATURES is in the fence. If an answer needs something the API or the mapper doesn't do today, the design intake after ratification slices that into its own story: S138's fence is the web app only.
- **2026-11-10: the owner settled what S129's draft asked about an "as of" line**, and Standings gained three views (S139, S129, S130). The line reads "Standings as of March 2, 2027", shows only when the day isn't today and names the day being viewed (*"the as of should only show if the date is not today"*; *"It's the day you're viewing."*). A past date offers and opens the views it would have on that day (*"Same rules as if that date were today."*), which S130's function does for any day it is given (S139's until the 2026-11-13 re-scope). AC 3 was updated to match: it named S129's "label line" and treated `Today` as an open question. Draw to S129's ratified amendment.
- The calendar on Standings is the scoreboard's component, so its game counts and favorite-team marks come with it unless AC 2's amendment says otherwise.
