**Gap:** S50 built the Postgres adapter and S51 runs local dev on it, but there is no production database: no Neon project, no real Hyperdrive config (`wrangler.jsonc` carries a placeholder id), no way to apply migrations to it, and the deployed Worker isn't composed on it. The owner, 2026-11-02: *"The Cloudflare deploy should be the top priority after we establish the production database."* Ordered by the owner (2026-11-02): S111, S51, S112, then this, then the deploy (S114). Sliced from the *Cloudflare deploy* Later theme.

**Impact:** Before S113, there was nowhere for the real app to keep its data. After it, a production database exists, its tables are created and kept up to date by one command, and the deployed app is wired to it, ready for the first deploy.

**Source:** Pillar: Dependable — a production database that keeps fans' data through restarts and backup restores, so the app can be counted on. Asked whether S112 may cite Delightful, and S113 and S114 Dependable. Approved by owner 2026-11-02: "yes those are good pillars to use"
