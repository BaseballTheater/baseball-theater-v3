**Gap:** ADR-020 layer 1: a cron wakes one `game-ingest:<gamePk>` Durable Object per in-window game; its alarm polls MLB, writes Postgres, **then** publishes to the game's registered hubs, with hub leases kept in its storage. At HEAD S16's `tickIngest` runs on `setInterval` in `local-server.ts`, and the baseline says "Not yet a deployed scheduled function". Inserted by the 2026-10-18 backlog review (two independent fresh-context reviewers, merged). The 2026-10-20 backlog review's duplication sweep found `functions/src/services/ingest.ts:70` deciding "final" inline (`codedGameState !== "F"`), which disagrees with `isFinalStatus` (`F`, `O`, `C`): a game-over game outside the window is never fetched. S48 rewrites that per-game decision, so AC 8 makes it one implementation.

**Impact:** Before S48, live games were only polled while a developer's laptop server was running. S48 impact: each live game gets its own always-recovering poller that saves every change before telling anyone about it.
