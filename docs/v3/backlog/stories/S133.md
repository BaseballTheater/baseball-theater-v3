**Gap:** The owner asked for a changelist page, a link to it from the update notice, a notification after updating that dismisses itself and links to it, and the big additions shown on both notifications (owner, 2026-11-08: *"The update dialog should link to it and a notification that auto dismisses after updating should show a link to it. Really big new additions should show on the update notification itself"*; asked which notification, *"Both"*). The ratified shell draws only the update-available notice (A6), with no link or notes, and nothing draws the page or the after-update notification, so S134 and S135 can't build them without designing in code (rule 18). On the first draft the owner took the big additions off the after-update notification and ruled out two boxes at once (owner, 2026-11-09, shown the A9 draft, where image 1 showed the after-update notification stacked above the update notice, each a message with "See what's new" and its buttons and neither listing additions, and image 2 the after-update notification listing the big additions: *"Image 1 here looks good. Image 2 is weird, no need to show that"*; asked which notices should stop listing them: *"There shouldn’t be two boxes ever. After it updates, we should see something similar to image 1, but it should tell the user the the update is complete instead"*).

**Impact:** Before S133, nothing showed what the changelist page or the new notifications look like. S133 impact: the owner approves the page, the link, the after-update notification and how big additions appear on the update notice, before S134 and S135 build them.
