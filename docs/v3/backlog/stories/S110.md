**Gap:** The entry JavaScript is 199,901 of its 200,000-byte budget (ADR-026; size-limit in the S70 and S19 ledger entries), up from 197,889 at S68/S69. `web/src/routes.tsx` imports every page eagerly (`GamePage`, `StandingsPage`, `SearchPage`, `SettingsPage`), so each page's code ships in the first download. The next UI stories add code (S75's masks and domain functions, S71's digest on the landing route) and would each fail `pnpm size`. Nothing in the backlog code-splits the routes. Inserted by the 2026-11-02 design intake review (two independent fresh-context reviewers, merged; raised by one). The owner chose lazy loading over a bigger budget (2026-11-02: *"Lazy loading would be better, with chunked JS files."*).

**Impact:** Before S110, the app's first download was 99 bytes under its size limit, so the next feature would fail the size check. S110 impact: the game, standings, search and settings pages download when first opened, so the scoreboard loads with room to grow.

**Source:** Pillar: Dependable — keeps the first download inside ADR-026's entry budget by loading the pages past the scoreboard on demand, as chunked JS files, so a slow page is caught by a check rather than by users. Asked whether the pages should load on demand or the budget be raised, and whether this story may cite Dependable as S54 and S62 do. Approved by owner 2026-11-02: "Lazy loading would be better, with chunked JS files." and "yes"
