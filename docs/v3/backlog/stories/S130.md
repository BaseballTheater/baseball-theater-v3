**Gap:** The owner wants Standings to show spring training, the regular season or the playoffs, with the fan able to switch (owner, 2026-11-10: *"I think the standings view should have an option. Basically, it should be capable of showing spring training, regular season, and playoffs."*), to say which day's standings these are when it isn't today, to celebrate the World Series winner in the off-season, and to title the page by what is shown (FEATURES, Standings row). The page (`web/src/pages/StandingsPage.tsx`) draws the one table it is given under the heading "Standings", spring training's like the regular season's. S139 and S140 put the views and the winner in the data; nothing shows them.

**Impact:** Before S130, Standings showed one table and spring training's looked like the real thing. S130 impact: a fan can switch between spring training, the regular season and the playoffs when each applies, the page opens on the one that matters that day, says "Standings as of" a past day, and celebrates the World Series winner in the off-season.

**Acceptance criteria** (checks `scripts/verify-S130.sh` performs)

1. **The switch.** The page asks for standings through `useStandings` with `view=default` when its address names no view, and with the address's `?view=` when it names one. It draws S129's switch from the answer: the views in `views.offered`, the answer's `view` marked. Choosing a view puts it in the address beside any `?date=`, which is kept, so the view can be linked and Back returns to the one before. When the address names a view other than `default` and the answer's `view` isn't that one (that day doesn't offer it), the page shows what came back and corrects the address without adding a history entry. An address that names no view, or `view=default`, is never corrected: it asks `view=default` on every visit, so the day's default opens, whatever view came back. The corrected address asks under a new cache key, so the table that came back stays on screen while it is asked for again: no loading state shows between the two. An answer with no `views` (cached from before S139) draws the table as today with no switch (RTL: each set of offered views S129 draws; choosing one; an address asking for a view not offered, asserting the table never leaves the screen and the loading state never shows after the first answer; an address with no `?view=`, and one with `?view=default`, each answered with a `view` that isn't `views.default`, asserting the address is unchanged; an answer without `views`).
2. **Each view.** Spring training's tables have no games-behind column; the regular season's keep it. The regular season before its first game and the playoffs list are drawn as S129 draws them, the playoffs list with no numbers. Which is drawn follows the answer's `view`, never the address or the calendar An answer with `view: "spring"` and no teams (the first spring morning, S139 AC 2 and AC 3; it can come back with `divisions: []`, which `StandingsPage` draws today as "No standings for this date." with no switch) draws what S129 draws for spring training with nothing to show yet, with the switch, so the fan can still choose the regular season (RTL with an answer of each view, the playoffs one with teams from two divisions, and an empty spring answer with `views.offered` of spring and the regular season, asserting the switch and S129's empty-spring text).
3. **The "as of" line.** When the address names a day that isn't MLB's today (`mlbToday`), the page says "Standings as of March 2, 2027" for that day, where S129 puts it: the day asked for, not the answer's `date` (a final table's `date` is its season's last day). With no day in the address, or today's, there is no line. The date is formatted by one named function in `web/src/format/datetime.ts` (RTL: a past day in each view; today's date in the address; no date).
4. **The World Series box.** When the answer has a `champion` and S129's rule for when the box shows is met, the page draws S129's box above the table: the winner's name and a link to the playoffs view that keeps the address's `?date=`. S129's rule is one named, tested function in `packages/domain` (ADR-025), given the answer's `champion` (with `wonOn`, the day the Series was won, S140), the answer's `view` and the day being viewed; the page calls it and never works the week out from `views.default` (unit tests: the sixth and seventh days after `wonOn`, the last day S129 says it stays and the day after, and no `champion`). Whatever in the box moves stays still for a fan whose device asks for reduced motion, as S129 says. No `champion`, or a day S129's rule excludes: no box (RTL for each).
5. **The title.** The page's heading and the browser tab's title read as S129 gives them for each view and for a day that isn't today. Only Standings sets the tab's title: leaving for another page puts back the title the app had (RTL: each view; a past day; navigating to the scoreboard and reading the tab's title).
