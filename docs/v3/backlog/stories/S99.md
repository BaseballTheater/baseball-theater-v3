**Gap:** MLB names a player of the game, with a stat summary and the win probability he added; BT doesn't keep it (owner, 2026-10-30: *"Also add stories to ingest all of this extra data."*).

**Impact:** Before S99, BT didn't know MLB's player of the game. S99 impact: BT keeps MLB's pick for each finished game — who, his line, and how much he swung the game — ready for a view to show.

**Source:** Feature: More MLB game data

**Scope files:** `fixtures/`, `packages/mlb-api/src/`, `packages/ports/src/`, `packages/domain/src/`, `functions/src/`, `functions/vitest.config.ts`, `openapi/`, `docs/v3/BACKLOG.md`, `docs/v3/backlog/`, `docs/v3/AUDIT.md`, `CHANGELOG.md`

**Work**

0. Write `scripts/verify-S99.sh` meeting the [Verify-script contract](#verify-script-contract). Run it against current HEAD and show the nonzero exit **before** building (rule 9).

**Acceptance criteria** (checks `scripts/verify-S99.sh` performs)

1. `fixtures/raw/potg-823823.json` holds MLB's response to `https://www.mlb.com/apps/player-of-the-game/game/json/winners/{gamePk}.json (gzip)` for 823823, recorded once with `BT_USE_LIVE_MLB=1` and committed; tests and local dev read it, never the network.
2. `packages/mlb-api` types the payload as named interfaces split by purpose and parses it with zod; a parse test runs on the recording, and `pnpm mlb:scan-drift` diffs it against the parser like the other payloads.
3. `MlbStatsClient` gains `fetchPlayerOfTheGame(gamePk)`, implemented by the fixture adapter and the HTTP adapter; ingest owns the call (ADR-002): no web code fetches it.
4. A mapper in `functions/src/mappers/` projects it into BT's own shape, `GameSnapshot.playerOfTheGame`, added to the game payload additively (regeneration test; `pnpm api:breaking` exits 0). The media pick and the fan pick, each player id, team id, summary and win probability added, a pick with no player absent; on 823823 the media pick is Ryan Zeferjahn (666171), "1.2 IP, 0 ER, K, BB", 40.7, and the fan pick is absent (test).
5. The source is optional: when the call fails or returns nothing, the field is absent and the game is served as before (test).
6. This file's S99 **Status** (story heading and top table) is `done`.

**Notes:**

- No view shows it yet; one that does is a new story with its design.
- **When to fetch it** (owner, 2026-10-30, *"Ok, agreed"*): mlb.com's Gameday config says player of the game exists from 2024 on (`playerOfTheGameMinYear: 2024`) and only for regular-season and postseason games (`playerOfTheGameGameTypes: ["R","F","D","L","W"]`); ingest calls the feed only for those games. BT does not ingest the config itself.
- **Local dev reads only bundled fixtures (2026-10-30 backlog review).** Since S45, `pnpm dev` runs the API in `wrangler dev`, and the Worker reads only the fixtures listed in `functions/src/adapters/fixtures/bundled.ts`; `fixtures/raw/` is not bundled (the file's header: the replay walk is for the Node capture tool). For AC 1's "local dev reads it", either bundle the new recording there or have `record-fixtures` (`functions/src/scripts/record-fixtures.ts`) write the projected field into `fixtures/game-823823.json`; `bundled.test.ts` fails when the fixture client reads a name the list lacks. The HTTP adapter (`functions/src/adapters/http/mlb.ts`) knows one `baseUrl` (statsapi); a feed on another host needs its own base URL, kept testable.
