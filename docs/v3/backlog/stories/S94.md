**Gap:** The content feed BT reads gives a video's play only through `guid`, and ABS challenge clips have none. MLB's GraphQL game content (`data-graph.mlb.com`, `getGamesByGamePks`) gives `playIdRef` on 18 of 823823's 25 videos — three of the five ABS clips among them — plus the recap and related articles (owner, 2026-10-30: *"Also add stories to ingest all of this extra data."*).

**Impact:** Before S94, BT had no way to tell which play an ABS challenge video shows. S94 impact: BT keeps MLB's own play link for those videos, and the game's related articles, so the next stories can connect videos to plays.

3. `MlbStatsClient` gains `fetchGameGraphContent(gamePk)`, implemented by the fixture adapter and the HTTP adapter; ingest owns the call (ADR-002): no web code fetches it.
4. A mapper in `functions/src/mappers/` projects it into BT's own shape, `GameSnapshot.videoPlayRefs and GameSnapshot.relatedArticles`, added to the game payload additively (regeneration test; `pnpm api:breaking` exits 0). Each video's `playIdRef` keyed by its slug / id, so it joins the content feed's videos; on 823823, 18 of the 25 videos carry one and every one is a real pitch `playId` in the live feed (test); related articles keep headline, blurb and URL.
5. The source is optional: when the call fails or returns nothing, the field is absent and the game is served as before (test).
