**Gap:** S114's production env (`wrangler.jsonc` env `production`) claims `baseball.theater` as its Cloudflare custom domain, and since S118 `.github/workflows/deploy.yml` deploys production on every push to `main` with no approval. Wrangler run non-interactively in CI overrides an existing DNS record for a custom domain, so the owner's first merge of `stage` into `main` would move `baseball.theater` off the Elastic Beanstalk (v2) site at once. The owner, 2026-11-07, on what the real production release gate is: *"changing the DNS away from the elastic beanstalk destination"*. Offered two ways out (production deploys to a temporary address and the owner cuts `baseball.theater` over by hand, or "don't merge into main until you're ready"), the owner chose: *"Do the temporary address"*. Asked "Is next.baseball.theater okay as production's temporary address, and can that story cite the Dependable pillar?": *"Agreed and yes"*.

**Impact:** Before S119, the first release of the new app would have silently replaced the current baseball.theater site the moment the owner merged into `main`. After it, production goes live at next.baseball.theater, the current site keeps running untouched, and switching baseball.theater to the new app is a separate, deliberate step the owner takes when ready, with a written way back.

**Source:** Pillar: Dependable — production first runs at a temporary address so the live v2 site keeps serving fans until the owner deliberately cuts DNS over, with a rollback written down.
