**Gap:** The Standings page and its API already answer for any day (`/standings?date=<date>`, `web/src/pages/StandingsPage.tsx`; `GET /api/v1/standings?date=`), but the page has no control for choosing one, and the owner asked for the scoreboard's date picker there (owner, 2026-11-09: *"can the standings page also have the date picker and show what the standings were at any given date?"*; told the page and the API already take a date, and offered its own stories, a fold into S129's design, or nothing: *"Add as its own stories (Recommended)"*).

**Impact:** Before S138, seeing the standings on a past date meant editing the address by hand. S138 impact: fans pick or type a date on Standings, with the same calendar the scoreboard has, and see the standings as they were that day.
